# 课程签到 · 西安交通大学（v2）

基于 **uni-app + uniCloud** 的多端课堂签到系统。管理员在 Web 端维护课程与教师，
学生打开就是「当前课程 + 倒计时 + 一个签到按钮」，不需要先选身份、也不需要先选课程。

> 这是课程作业的第二版。第一版是微信小程序 + 微信云开发（5 张表、首页选身份），
> 位于仓库根目录，作为对比保留，不再维护。两版的差异见本文末尾。

---

## 一、它解决什么问题

第一版能用，但用起来有三处别扭：

1. 学生要先在首页点「学生登录」，再输学号姓名，再选课程 —— 三次操作才到签到页；
2. 教师没有位置，课程上只挂了一个教师名字字符串；
3. 只能在小程序里用，分享给同学得先加体验成员。

第二版对应改了三件事：**自动识别身份、教师成为用户角色、换 uni-app 做多端**。
核心交互收敛成一个按钮。

## 二、功能

### 用户端（H5 / Android / iOS）

| 功能 | 说明 |
|---|---|
| 登录 / 注册 | 学号（工号）+ 密码；注册一律是学生，教师与管理员由管理员创建 |
| 自动识别身份 | 登录令牌里带角色，学生进签到页，教师 / 管理员进管理端，不用手选 |
| 当前课程 | 按「今天星期几 + 当前时间」自动匹配，页面只读展示课程与时间 |
| 倒计时 | 距开课还有多久、签到什么时候开、什么时候截止 |
| 一个签到按钮 | 四态：可签到 / 未到时间 / 已签到 / 超出范围 |
| 定位签到 | 调用原生定位，经纬度上报云端裁决；定位失败可「演示定位」走通流程 |
| 我的记录 | 按时间倒序展示本人签到记录 |

### Web 管理端（H5，PC 布局）

| 页面 | 功能 |
|---|---|
| 概览 | 课程 / 教师 / 学生 / 今日签到四项统计，今日课程与最近签到 |
| 课程信息维护 | 新增、编辑、停用、删除；设置点位、距离阈值、上课时间 |
| 课程安排 | 周课表视图，7 列对应周一到周日 |
| 教师分配 | 课程 ↔ 教师，选择即保存；可新增教师账号 |
| 签到记录 | 按课程 / 日期 / 关键字筛选，删除记录，导出 Excel |

教师登录后只开放「概览 + 签到记录」，且只能看到自己课程的记录。

## 三、技术栈

| 层 | 选型 |
|---|---|
| 前端 | uni-app（Vue 3，Options API），一套代码编译到 H5 / App |
| 后端 | uniCloud 云函数（阿里云版），单个 `api` 函数 + action 分发 |
| 数据库 | uniCloud 云数据库（MongoDB 兼容），3 个集合 |
| 存储 | uniCloud 云存储（导出 Excel 中转） |
| 依赖 | `xlsx`（仅导出用） |

**为什么只有一个云函数**：三张表的体量很小，拆成 4~5 个函数会让公共代码被迫复制多份
（uniCloud 每个函数独立打包）。单函数 + action 分发，公共逻辑只有一份，部署也只上传一次。

## 六、三张表

| 集合 | 作用 | 关键约束 |
|---|---|---|
| `users` | 学生 / 教师 / 管理员统一身份 | `account` 唯一索引 |
| `courses` | 课程、时间、点位、阈值 | 经纬度为标量，结构上不支持多点位 |
| `sign_records` | 谁、在哪节课、何时、离点位多远 | **唯一索引** `userId + courseId + sessionDate` |

## 七、几条关键设计

**1. 去重键为什么带 `sessionDate`**

课程表里一条记录代表「每周三 08:00 的这门课」。如果只用 `userId + courseId` 做唯一键，
学生第一周签过之后，**整个学期都签不了**。加上课次日期后，同一节课只能签一次，
下一周是新的一节。这仍然只用三张表，没有引入课次表。

**2. 距离与时间窗都在云端判定**

客户端只上报经纬度，页面上的「距点位 23 米」仅用于展示。
即使改前端、直接调云函数，也绕不过服务端的 Haversine 计算和时间窗校验。

**3. 超出范围时按钮仍然可点**

如果按钮在超范围时直接禁用，学生改前端就能绕过。所以按钮照常可点，
由云端返回 `410` 并拒绝写库，同时把实际距离告诉学生。

**4. 客户端不直连数据库**

三个集合权限全部为「所有用户不可读写」，只能经过云函数。
原因是默认权限模型表达不了「管理员读全部、学生不绑 openid」这两个需求。

**5. 登录态不占表**

用 HMAC 签名的无状态令牌（`payload.signature`），服务端不存 session，
避免为了登录态再加第四张表。

## 八、已知取舍

| 取舍 | 原因 |
|---|---|
| 一门课只支持一位教师 | 三张表的约束。要多教师就得加中间表，与「先做好三张表」冲突 |
| 不支持调课 / 补签 | 本轮需求没有；课程时间固定为周课表 |
| 不区分迟到 / 缺勤 | `result` 字段预留，本轮固定 `success` |
| 导出为全量内存过滤 | 课程作业量级（千条以内）够用；上万条需要改成数据库分页 |
| 演示定位 | 桌面浏览器或无 HTTPS 时定位不可用，提供点位附近的模拟坐标走通流程，页面会明确标注 |
| H5 与 App 坐标系不同 | App 用 gcj02（与高德/腾讯一致），H5 只能用 wgs84。H5 请求 gcj02 需要配置地图服务商 key，否则 uni-app 会直接报 `map provider not configured`。因此 H5 的定位结果与课程点位之间存在数百米量级的坐标系偏差，真机做精确判定要用 App 端 |
| 鸿蒙未打包 | uni-app 支持鸿蒙，但需要华为开发者账号与签名，本轮交付以 H5 为主 |

## 九、与第一版的差异

| 维度 | 第一版（仓库根目录） | 第二版（本目录） |
|---|---|---|
| 载体 | 微信小程序 | uni-app 多端（H5 / App） |
| 后端 | 微信云开发 | uniCloud（阿里云） |
| 角色 | 学生 / 管理员，首页手选 | 学生 / 教师 / 管理员，自动识别 |
| 教师 | 课程里的一个文本字段 | 用户角色，可登录、可查自己课程的记录 |
| 表数 | 5 个集合 | 3 个集合 |
| 入口 | 登录 → 选课程 → 签到 | 打开即见当前课程，一个按钮 |
| 管理端 | 小程序内嵌页面 | 独立 Web 管理端 |
| 去重 | 课程 + 设备 | 用户 + 课程 + 课次日期 |
