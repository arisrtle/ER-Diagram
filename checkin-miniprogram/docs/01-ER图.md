# 01 · ER 图

系统有 4 个实体：**管理员、课程、学生、签到记录**。签到记录是学生与课程之间多对多联系的落地实体，因为它自带大量属性（设备 ID、位置、距离、时间、来源），也需要被管理员单独增删改。

## 概念 ER 图（Chen 表示法）

![概念 ER 图](er/er-concept.png)

| 联系 | 两端 | 基数 | 说明 |
| --- | --- | --- | --- |
| 创建 | 管理员 — 课程 | 1 : N | 一位管理员可以创建多门课程，每门课程有一个创建者 |
| 包含 | 课程 — 签到记录 | 1 : N | 一门课程有多条签到记录，每条记录属于一门课程 |
| 提交 | 学生 — 签到记录 | 1 : N | 一名学生可以在多门课程签到；**每门课程至多一条** |
| 维护 | 管理员 — 签到记录 | 1 : N | 管理员修改、删除、补录签到记录 |

签到点位没有单独建实体：业务明确「一门课程只有一个签到点位」，所以纬度、经度、距离阈值直接作为课程的属性。

## Mermaid 版本

GitHub 会直接渲染下面的代码块，方便在线查看。

```mermaid
erDiagram
    ADMINS ||--o{ COURSES : "创建 createdBy"
    COURSES ||--o{ CHECKINS : "包含 courseId"
    STUDENTS ||--o{ CHECKINS : "提交 studentNo"
    ADMINS ||--o{ CHECKINS : "维护 updatedBy"

    ADMINS {
        string _id PK "微信 OPENID"
        string nickname "昵称"
        string status "active / pending"
        date createdAt
        date lastLoginAt
        date approvedAt
    }
    COURSES {
        string _id PK "课程 ID"
        string name "课程名称"
        string note "备注"
        number latitude "点位纬度 gcj02"
        number longitude "点位经度 gcj02"
        string address "地点名称"
        number radius "距离阈值(米)，默认 50"
        string createdBy FK "admins._id"
        date createdAt
        date updatedAt
    }
    STUDENTS {
        string _id PK "学号"
        string name "姓名"
        string className "班级"
        date updatedAt "最近导入时间"
    }
    CHECKINS {
        string _id PK "课程ID_设备ID"
        string courseId FK "courses._id"
        string studentNo FK "students._id"
        string name "姓名快照"
        string className "班级快照"
        string deviceId UK "设备 ID"
        string openid "微信指纹"
        number latitude
        number longitude
        number accuracy "定位精度(米)"
        number distance "距点位(米)"
        number radius "签到时的阈值"
        date checkedAt "签到时间"
        string source "student / admin"
        string remark "备注"
        bool deleted "软删除"
        string updatedBy FK "admins._id"
    }
```
