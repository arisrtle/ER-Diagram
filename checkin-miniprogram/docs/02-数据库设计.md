# 02 · 数据库设计

使用微信云开发数据库（文档型，类 MongoDB）。根据 [ER 图](01-ER图.md) 建 4 个集合。

**访问方式：** 小程序端不直接读写数据库，全部经过云函数 `api`。所以 4 个集合的权限都设为「**所有用户不可读写**」（云开发控制台 → 数据库 → 权限设置 → 自定义安全规则 `{"read": false, "write": false}`），云函数用管理员权限访问，不受影响。这样学生无法绕过距离和次数校验直接写签到记录。

**坐标系：** 所有经纬度都是 `gcj02`（`wx.getLocation` 与 `wx.chooseLocation` 的默认坐标系），点位与学生位置在同一坐标系下，直接计算球面距离。

## 1. admins（管理员）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | **主键，微信 OPENID**。由云函数上下文 `cloud.getWXContext()` 提供，前端无法伪造 |
| `nickname` | string | 是 | 昵称，1–20 字 |
| `status` | string | 是 | `active` 已启用；`pending` 待审核 |
| `createdAt` | date | 是 | 创建（申请）时间 |
| `lastLoginAt` | date | 否 | 最近一次登录时间 |
| `approvedAt` | date | 否 | 审核通过时间 |

规则：系统还没有任何启用的管理员时，第一个用微信授权登录的人自动成为管理员；之后的人提交申请（`pending`），由任一管理员通过或拒绝。

## 2. courses（课程，含签到点位）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 主键，数据库自动生成 |
| `name` | string | 是 | 课程名称，1–40 字。建议一节课一条，如「数据库原理 第 5 周」 |
| `note` | string | 否 | 备注，≤ 60 字 |
| `latitude` | number | 是 | 签到点位纬度（gcj02），−90 ~ 90 |
| `longitude` | number | 是 | 签到点位经度（gcj02），−180 ~ 180 |
| `address` | string | 否 | 地点名称，来自地图选点，≤ 80 字 |
| `radius` | number | 是 | 距离阈值（米），整数 10–1000，**默认 50** |
| `createdBy` | string | 是 | 外键 → `admins._id` |
| `createdAt` | date | 是 | 创建时间 |
| `updatedAt` | date | 是 | 更新时间 |

一门课程只有一个点位，所以点位字段直接放在课程上，不支持多点位。

## 3. students（学生）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | **主键，学号**。字母、数字、短横线，3–32 位 |
| `name` | string | 是 | 姓名，≤ 20 字 |
| `className` | string | 是 | 班级，≤ 40 字 |
| `updatedAt` | date | 是 | 最近一次导入时间 |

用学号做主键：同一学号重复导入即覆盖更新，不会出现重复学生。学生登录只校验「学号 + 姓名」与这张表匹配，不设密码，也不绑定微信 openid。

## 4. checkins（签到记录）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | **主键**。学生签到：`课程ID_设备ID`；管理员补录：`课程ID_admin_学号` |
| `courseId` | string | 是 | 外键 → `courses._id` |
| `studentNo` | string | 是 | 外键 → `students._id` |
| `name` | string | 是 | 姓名快照（签到时的名单数据，名单后来变动不影响历史记录） |
| `className` | string | 是 | 班级快照 |
| `deviceId` | string | 否 | 设备 ID。小程序首次启动时生成并持久保存在本机；补录为 `null` |
| `openid` | string | 否 | 签到时调用者的微信 OPENID，作为设备指纹的补充，**不用于学生登录** |
| `latitude` | number | 否 | 签到时纬度；补录为 `null` |
| `longitude` | number | 否 | 签到时经度；补录为 `null` |
| `accuracy` | number | 否 | 定位精度（米），来自 `wx.getLocation` |
| `distance` | number | 否 | 服务端计算的到点位距离（米，保留 1 位小数） |
| `radius` | number | 是 | 签到当时课程的距离阈值（之后改阈值不影响历史判断） |
| `checkedAt` | date | 是 | 签到时间（服务端时间） |
| `source` | string | 是 | `student` 学生签到；`admin` 管理员补录 |
| `remark` | string | 否 | 备注，≤ 60 字 |
| `deleted` | bool | 是 | 软删除标记，默认 `false` |
| `deletedAt` / `deletedBy` | date / string | 否 | 删除时间 / 删除人（→ `admins._id`） |
| `updatedAt` / `updatedBy` | date / string | 否 | 最近修改时间 / 修改人（→ `admins._id`） |
| `createdBy` | string | 否 | 补录人（→ `admins._id`） |

### 业务约束如何落到数据上

| 约束 | 实现 |
| --- | --- |
| 同一课程、同一设备 ID 只能签到 1 次，无例外 | `_id = 课程ID_设备ID`。主键唯一，即使同一瞬间重复提交也只有一条能写入成功 |
| 签到成功后不可再次提交、不允许重试 | 写入前检查 `(courseId, studentNo)` 是否已有记录（**包括已删除的**），有则拒绝 |
| 清缓存换设备 ID 也不能代签 | 同时检查 `(courseId, openid)`：同一部手机上的同一个微信号会被识别 |
| 超出阈值禁止签到 | 云函数用 Haversine 公式计算 `distance`，`distance > radius` 时拒绝，不写入 |
| 删除不会让人重签 | 删除是软删除，记录仍占着上述位置；列表、导出只显示 `deleted = false` 的记录 |
| 管理员补录 | 学生有已删除的记录时复用该条（恢复并标记 `source = admin`），否则新建；始终保证同课程同学号只有一条 |

### 不做的事（与任务书边界一致）

没有签到起止时间字段、没有迟到 / 缺勤状态、没有消息推送、没有操作日志集合。

## 5. 索引

在云开发控制台 → 数据库 → 对应集合 → 索引管理中添加：

| 集合 | 索引字段 | 属性 | 用途 |
| --- | --- | --- | --- |
| checkins | `courseId` 升序, `studentNo` 升序 | **唯一** | 同一课程同一学号只能一条（数据库层兜底） |
| checkins | `courseId` 升序, `openid` 升序 | 非唯一 | 同一微信判重 |
| checkins | `deviceId` 升序 | 非唯一 | 学生端查询这台手机的签到状态 |
| checkins | `studentNo` 升序 | 非唯一 | 学生端查询自己的签到状态 |
| checkins | `deleted` 升序, `courseId` 升序, `checkedAt` 降序 | 非唯一 | 管理端按课程列出记录 |
| admins | `status` 升序 | 非唯一 | 判断是否已有管理员 |
| students | `className` 升序 | 非唯一 | 按班级筛选 |

`_id` 自带唯一索引，无需添加。
